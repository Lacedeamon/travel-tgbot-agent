# Mr. Robot (AI-турагент Островка)

Прототип автономного AI-турагента в Telegram на базе архитектуры Tool Calling с интеграцией структурированного SQL-поиска и кэшированием контекста. Агент проводит пользователя от абстрактного запроса до готового маршрута, подбирая отели на основе реальных данных, аргументируя свой выбор и имитируя процесс оформления заказа.

- Видео-скринкаст: https://drive.google.com/file/d/1t3lHrg_-a80TjIb5fNmul2PN3bznm6Yy/view?usp=sharing

## Быстрый старт

```bash
git clone https://github.com/ostrovok-hackathon-2026/mr-robot.git
cd mr-robot
cp .env.example .env
```

# Обязательно заполните TG_BOT_TOKEN и OPENAI_API_KEY в файле .env перед запуском!
docker compose up --build
Бот будет доступен в Telegram. Сервис проверки состояния работает по адресу: http://localhost:8080/health.

Зависимости и переменные окружения
Рекомендованные ресурсы:

2 CPU cores

2GB RAM

Postgres 16 (в docker-compose.yml как db)

Redis (в docker-compose.yml как redis)

Переменные окружения (задаются в .env):

APP_PORT (по умолчанию 8080)

DB_URL (по умолчанию postgres://app:app@db:5432/app?sslmode=disable)

REDIS_ADDR (по умолчанию redis:6379)

TG_BOT_TOKEN — токен Telegram-бота

OPENAI_API_KEY — ключ API для VseGPT/OpenAI

OPENAI_BASE_URL — базовый URL (по умолчанию https://api.vsegpt.ru/v1)

Сидирование
В проекте реализованы встроенные Go-миграции (internal/storage/pg/migrations). База данных, таблицы и стартовый набор данных (50+ отелей Турции с реальными ценами и характеристиками) инициализируются и сидируются автоматически при первом запуске приложения (docker compose up). Никаких ручных команд для загрузки данных выполнять не нужно.

Маршруты/доступ
Поскольку основным интерфейсом является Telegram-бот, веб-интерфейс (UI) не предусмотрен.

/health — 200 OK, JSON { "status": "ok" } (используется для Docker Healthcheck)

Работа с ботом (Вместо веб-интерфейса)
Для тестирования логики необходимо написать Telegram-боту, чей токен указан в конфигурации.
Базовые команды:

/start — запуск бота

/help — справка по общению

/reset — принудительная очистка кэша Redis (истории диалога и корзины) для начала новой сессии

/checkout — принудительный вывод карточки текущего заказа
